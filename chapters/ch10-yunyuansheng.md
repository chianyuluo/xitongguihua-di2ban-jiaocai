# Chapter 10: 云原生系统规划

## Core Idea
云原生是应用系统现代化的方向：用容器、微服务、DevOps 等实现弹性、敏捷与高可用。规划重点是技术栈选型与组织研发模式转型。

## Frameworks Introduced
- **云原生技术栈（CNCF 视角）**：容器与编排（Docker/K8s）、微服务、服务网格（Service Mesh）、声明式 API、不可变基础设施、DevOps。
- **12 要素应用（12-Factor）**：基准代码、依赖、配置、后端服务、构建发布运行分离等，指导云原生应用设计。
- **微服务拆分**：按业务能力/领域（DDD）拆分，独立部署、独立伸缩。
- **DevOps 闭环**：持续集成（CI）→持续交付（CD）→持续部署，配合可观测性。

## Key Concepts
- **容器**：轻量级虚拟化，镜像封装、秒级启停。
- **不可变基础设施**：发布即替换而非修改，提升一致性。
- **服务网格**：把通信、限流、熔断等治理能力下沉到 Sidecar。
- **Serverless**：更极致的弹性，按调用计费。

## Mental Models
- 上云≠云原生；判断是否真正云原生：看是否容器化+微服务+CI/CD+弹性。
- 微服务不是越细越好，按业务边界（DDD）拆，避免分布式单体。

## Anti-patterns
- 把单体应用直接容器化就自称云原生，无微服务与 CI/CD。
- 微服务过度拆分，运维与网络复杂度失控。

## Key Takeaways
1. 云原生=容器+微服务+DevOps+服务网格+声明式API。
2. 12-Factor 是云原生应用设计准则。
3. 不可变基础设施提升发布一致性。
4. CI/CD 闭环是敏捷交付核心。
5. 微服务按业务领域（DDD）拆分。

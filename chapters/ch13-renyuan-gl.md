# Chapter 13: 人员管理

## Core Idea
人员是 IT 服务四要素之首。本章讲如何设计服务组织、定角色职责、建能力模型、做培训与考核，把"人"这一最活跃要素管到位。

## Frameworks Introduced
- **IT 服务组织设计**：按职能（服务台、运维、研发、质量）或按客户/产品线划分，明确汇报线。
- **角色职责矩阵（RACI）**：谁负责(R)、谁批准(A)、咨询(C)、知会(I)，避免职责真空。
- **人员能力模型**：知识、技能、经验、素养四维度，分级（初级/中级/高级/专家）。
- **绩效考核（PI）**：以服务指标（SLA 达成、事件解决率）而非工时评价。

## Key Concepts
- **关键角色**：服务经理（对服务质量总责）、事件/问题经理、变更经理、配置管理员。
- **知识管理**：知识库建设与共享，降低对个人依赖。
- **培训体系**：上岗认证 + 持续赋能。
- **团队建设**：梯队、激励、稳定性。

## Mental Models
- 组织设计先看"岗位职责是否闭环"，再用 RACI 排查扯皮点。
- 人员能力短板是服务质量的天花板，优先补关键角色。

## Anti-patterns
- 只设岗位不赋权，服务经理有责无权。
- 考核看工作量不看 SLA，导致"忙而不优"。

## Key Takeaways
1. 人员是四要素首位，组织设计+角色职责是基础。
2. RACI 用于厘清跨角色协作。
3. 能力模型按知识/技能/经验/素养分级。
4. 考核以服务指标为准，知识管理降依赖。

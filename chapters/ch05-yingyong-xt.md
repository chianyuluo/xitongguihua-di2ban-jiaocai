# Chapter 5: 应用系统规划

## Core Idea
应用系统规划把业务需求转化为应用架构：明确"要建哪些业务系统、如何集成、如何演进"。核心是业务—应用映射与应用集成策略。

## Frameworks Introduced
- **应用架构设计三视图**：功能视图（系统做什么）、数据视图（系统管什么数据）、集成视图（系统间怎么连）。
- **业务—应用映射矩阵**：每行一个业务域，每列一个应用系统，标注支撑关系，识别重复与缺口。
- **应用集成层次**：界面集成→数据集成→应用集成→过程集成（由浅入深）。
- **应用系统分类**：事务处理（TPS）、管理信息（MIS）、决策支持（DSS）、协作系统、智能系统。

## Key Concepts
- **应用系统生命周期**：规划→设计→开发→部署→运维→退役。
- **应用集成（EAI）**：ESB、API 网关、消息中间件是常用手段。
- **遗留系统演化策略**：淘汰、保留、改造、迁移、外包（5 选）。

## Mental Models
- 规划新系统时先画"业务域×应用"矩阵，避免烟囱式重复建设。
- 集成顺序：能数据集成就别硬做过程集成，循序渐进降风险。

## Anti-patterns
- 只按部门建系统，不做企业级应用架构，导致信息孤岛。
- 把"界面集成"当成"系统打通"的终点，未解决数据一致性。

## Key Takeaways
1. 应用架构三视图（功能/数据/集成）是规划骨架。
2. 业务—应用映射矩阵用于识别冗余与缺口。
3. 集成由浅入深：界面→数据→应用→过程。
4. 遗留系统有淘汰/保留/改造/迁移/外包五种策略。

# Chapter 12: 信息系统服务管理

## Core Idea
信息系统服务管理（ITSM）以"服务生命周期"为主线，用**四要素（人员 / 资源 / 技术 / 过程）**保障服务质量，对齐 ISO 20000 / ITIL。本章是系规案例与论文的高频章。

## Frameworks Introduced
- **服务生命周期 5 阶段**：战略规划 → 服务设计实现 → 服务运营提升 → 服务退役终止 → 持续改进与监督（注意顺序：设计实现在前、运营提升在后、退役终止、最后持续改进）。
- **服务四要素（第2版）**：**人员、资源、技术、过程**（严禁写成 PPTR）。人员=组织与角色；资源=知识库/工具/备件；技术=平台与手段；过程=标准化流程。
- **常见服务管理过程 8 个（口诀"级报事件问配变发安"）**：级别管理、报告管理、事件管理、问题管理、配置管理、变更管理、发布部署管理、安全保密管理。
- **服务质量评价 3 模型**：相关方模型、互动模型、质量模型。

## Key Concepts
- **事件 vs 问题**：事件=影响服务的突发状况（恢复）；问题=找根因（防复发）。
- **变更 vs 发布**：变更=修改审批；发布=交付到生产。
- **配置管理（CMDB）**：记录配置项（CI）及关系，是其他过程的底座。
- **服务标准化**：服务产业化 + 服务标准，提升可复制性。

## Mental Models
- 服务出问题先"事件"恢复、再"问题"求根因；改之前走"变更"、上之前走"发布"。
- 四要素失衡：人不对、工具缺、技术旧、流程乱，任一项都会拉垮服务质量。

## Anti-patterns
- 写成"PPTR"或"人员/过程/技术/资源"顺序错（第2版固定为人员/资源/技术/过程）。
- 把生命周期阶段顺序记错（设计实现→运营提升→退役终止→持续改进）。
- 混淆事件与问题、变更与发布。

## Key Takeaways
1. 生命周期 5 阶段顺序固定：战略→设计实现→运营提升→退役终止→持续改进。
2. 四要素=人员/资源/技术/过程（死记，禁用 PPTR）。
3. 8 个过程口诀"级报事件问配变发安"。
4. 事件恢复、问题求根因；变更审批、发布交付。
5. CMDB 是配置管理底座。

# Chapter 17: 信息系统项目管理

## Core Idea
信息系统以"项目"方式建设，建成后再转入"服务"运营。本章把项目管理基础与 IT 服务管理衔接：用五大过程组和十大领域管好交付，再平稳移交运营。

## Frameworks Introduced
- **五大过程组**：启动→规划→执行→监控→收尾（贯穿全程）。
- **十大知识领域**：整合、范围、进度、成本、质量、资源、沟通、风险、采购、干系人管理。
- **项目生命周期**：预测型（瀑布）/适应型（敏捷）/混合型，按需求稳定性选。
- **项目→服务衔接**：验收、知识转移、运维预案，避免"建完没人管"。

## Key Concepts
- **三重约束**：范围、进度、成本（加质量为四重）。
- **里程碑/基线**：范围/进度/成本基线，变更走控制。
- **关键路径（CPM）**：决定最短工期的活动链。
- **项目治理**：与 Ch11 对齐，保证投资对齐战略。

## Mental Models
- 需求稳定用预测型，需求易变用适应型；混合最常用。
- 项目收尾不只签字，要"带运维预案+知识转移"移交给服务管理。

## Anti-patterns
- 项目结束即解散团队，运营无文档无预案（移交断层）。
- 过程组与领域割裂，规划时忽略干系人与风险。

## Key Takeaways
1. 五大过程组 + 十大领域是项目管理骨架。
2. 生命周期按需求稳定度选预测/适应/混合。
3. 三重约束（范围/进度/成本）加质量。
4. 项目到服务的平稳移交是关键一跳。
